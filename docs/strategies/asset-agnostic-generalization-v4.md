# 资产无关稀疏配置 V4：最终冻结泛化验证协议

> 状态：研究候选，尚未替换 App 当前推荐策略
> 引擎入口：`AssetAgnosticBacktestEngine.runSparseV3`
> 冻结参数：`AssetAgnosticStrategyConfig.frozenV4`
> 纪律：本协议、参数和 PASS 门槛必须在第三批 holdout 历史下载前固定；运行后不得再修改 V4 并把同一批市场继续称为 OOS。

## 1. 前两次真实 OOS 结果

V2 与 V3 都保留失败记录，不做结果覆盖：

- V2 第一次 8 国 OOS：篮子 Sharpe 0.346、最大回撤 31.36%，FAIL；
- V3 第二次 8 国 OOS：篮子 Sharpe 0.297、最大回撤 20.27%，FAIL；唯一未过的核心门槛是 Sharpe >= 0.45；
- V3 第二批数据做零成本归因时 Sharpe 为 0.402，说明信号具有弱正优势，但 1% 单边成本显著侵蚀收益效率。

因此前两批国家市场及旧 Dow/Hang Seng/Nikkei/中国/WTI 诊断集从 V4 开始全部只能作为开发数据。

## 2. V4 的结构变化

V4 不增加任何国家、ticker 或地区规则，而是针对泛化中暴露的交易摩擦和时间尺度问题做最小化修改：

- 目标复核由 42 个共同交易日放慢到 105；
- 趋势过滤由 MA200 放慢到 MA250；
- 中期动量由 126 日改为 105 日；
- 长期动量保持 252 日，短期动量保持 63 日；
- 目标年化波动保持 7.5%；
- 最多持有 8 个资产、单资产常规上限 20%；
- 执行偏离带由 42% 放宽到 55%；
- 新旧目标总权重差低于 36% 时优先不交易；
- 单边交易费仍为 1.00%，滑点仍为 0.05%；
- T−1 决策、T 收盘执行，不融资、不做空、现金收益设为 0；
- 核心计算继续要求 ticker 重命名不变性。

冻结前最后一次 27 点局部开发网格中，V4 选定参数在三套已暴露数据上的最差篮子 Sharpe 为 0.448、最差最大回撤 18.48%。开发集没有被硬调到 0.45 以上；V4 在此停止调参，最终由未见数据判定。

数据通过 FRED/Nasdaq Daily Index Data 获取。若个别系列不可用，至少需要 6 个有效市场才能给出 PASS。

## 4. PASS 门槛

V4 不降低 V2/V3 的标准，必须同时满足：

1. 至少 6 个第三批 holdout 市场形成有效回测；
2. 单资产 Sharpe > 0 的比例 >= 62.5%；
3. 单资产 Sharpe 中位数 >= 0.20；
4. holdout 篮子 CAGR > 0；
5. holdout 篮子 Sharpe >= 0.45；
6. holdout 篮子最大回撤 <= 25%；
7. holdout 篮子最大回撤 <= 同资产等权买入持有最大回撤；
8. 全部 ticker 改成匿名名称后，CAGR / MDD / 波动 / Sharpe / 交易次数在 1e-9 容差内一致；
9. 全部结果计入 1.00% 单边交易费和 0.05% 单边滑点；
10. 最终结果运行后，不允许再用这批市场调参并重新宣称 OOS。

## 5. 结论边界

这项测试验证的是价格路径与风险配置规则的跨市场泛化，不等同于人民币投资者可直接实现的收益。国家指数以各自指数点位运行，没有加入 FX、具体 ETF 跟踪误差、管理费、税费、时区差和产品可交易约束。若 V4 通过，也只能晋级为“泛化研究候选”，还需要可交易产品层验证后才能考虑替换 App 当前生产策略。

## 6. 冻结 V4 最终结果

第三批 8 个市场全部成功获取完整历史，主要区间为 2001-03-30—2026-08-12。下载前已完成 V4 参数、协议和验证二进制冻结；随后只运行一次正式验证。

单市场结果全部为正 Sharpe，单资产 Sharpe 中位数为 0.266，ticker 重命名不变性 PASS。跨市场篮子为：

- CAGR：2.28%；
- 最大回撤：26.70%；
- 年化 Sharpe：0.417；
- 全期累计换手：8.08x；
- 交易记录：123；
- 等权买入持有最大回撤：69.03%；
- 等权买入持有 Sharpe：0.384。

最终判定：**FAIL**。未通过两条预注册硬门槛：篮子 Sharpe 0.417 < 0.450，最大回撤 26.70% > 25%。其余门槛通过。

这意味着目前的资产无关价格-only策略已经展示出较强的一致性风险控制和跨市场正收益倾向，但还不能被诚实地称为“通过泛化验证”。V4 之后不再继续更换新的国家 holdout 直到撞出 PASS；如继续研究，应改用预先定义的跨市场嵌套验证/时间走步验证，或引入真正新增的信息源，再建立新的独立验证协议。
