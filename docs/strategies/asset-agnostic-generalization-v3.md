# 资产无关稀疏配置 V3：第二次冻结泛化验证协议

> 状态：研究候选，尚未加入 App 精选策略目录
> 生产候选入口：`AssetAgnosticBacktestEngine.runSparseV3`
> 冻结参数：`AssetAgnosticStrategyConfig.frozenV3`
> 冻结原则：本文件、V3 参数与最终 PASS 门槛必须在下载第二批 holdout 历史之前固定；第二批 holdout 的结果不得用于继续修改 V3 后再宣称同一批数据为 OOS。

## 1. 为什么有 V3

V2 第一次正式资产 OOS 验证没有通过，结果必须保留而不能覆盖：

- 8/8 个国家市场单独运行均得到正 Sharpe；
- 单资产 Sharpe 中位数 0.257；
- 跨市场篮子 CAGR 2.02%；
- 跨市场篮子 Sharpe 0.346，低于预注册的 0.45；
- 跨市场篮子最大回撤 31.36%，高于预注册的 25%；
- 当时冻结二进制的 ticker 重命名不变性也失败。

因此 V2 的 Korea/Germany/UK/France/Australia/India/Brazil/Canada 八国数据从 V3 开始只能作为开发证据，不再具有 OOS 资格。

V3 开发同时发现并修复两类引擎问题：

1. 原通用引擎的组合回撤状态在一处使用了 T 日执行价格计算，虽然价格/动量信号仍是 T−1，但该组合状态不够严格；`runSparseV3` 改为只使用截至 T−1 已经形成的组合净值和历史峰值生成决策状态。
2. ticker 重命名可能改变字典遍历、浮点求和和极小边界比较；V3 的核心分配、风险估计和买入需求改为按原始输入顺序的数组进行确定性运算，重命名测试必须完全一致。

开发阶段也试验过“每日快速风险层”，但在 1% 单边交易费下产生了过高换手，故没有进入冻结 V3。最终 V3 刻意保持简单：慢速趋势、风险预算、宽交易带、低换手。

## 2. 冻结 V3 参数

- T−1 生成目标，T 日收盘执行；
- 初始资金：100,000；
- 单边交易费：1.00%；
- 单边滑点：0.05%；
- 不做空、不融资、不允许负现金；
- 现金收益率在本泛化实验中设为 0，避免用现金利息抬高策略 Sharpe；
- 预热：252 个共同交易会话；
- 目标复核：每 42 个共同交易会话；
- 动量窗口：63 / 126 / 252；
- 趋势过滤：MA200；
- 波动与协方差窗口：63；
- 目标年化风险：7.5%；
- 最多持有 8 个满足趋势条件的资产；
- 单资产目标上限：20%（当合格资产数量太少时，仅为保证权重可行性自动放宽到 `1/N`）；
- 执行偏离带：42%；
- 新旧目标总权重差低于 24% 时优先保持旧目标；
- 候选资产只按动量、波动、下行波动、趋势效率与相互正相关程度排序/分配；
- 根据预测组合波动、趋势宽度和截至 T−1 的组合回撤缩放总风险；
- 策略代码不得按 ticker、国家、地区或资产标签分支。

## 5. 最终 PASS 门槛

为避免失败后降低标准，V3 **沿用 V2 的核心门槛**，不因 V2 失败而放宽：

1. 至少 6 个第二批 holdout 市场具有足够历史；
2. 单资产独立运行时，Sharpe > 0 的比例至少 62.5%；
3. 单资产 Sharpe 中位数至少 0.20；
4. 所有可用 holdout 组成的资产无关篮子 CAGR > 0；
5. holdout 篮子 Sharpe >= 0.45；
6. holdout 篮子最大回撤 <= 25%；
7. holdout 篮子最大回撤不得高于同资产等权买入持有；
8. ticker 全部改成匿名名称后，CAGR / MDD / 波动 / Sharpe / 交易次数必须在 1e-9 数值容差内一致；
9. 所有结果继续计入 1.00% 单边交易费与 0.05% 单边滑点；
10. 最终验证运行后，不允许再修改 `frozenV3` 并在同一第二批 holdout 上重新宣称 OOS PASS。

仍不要求策略 Sharpe 必须高于买入持有 Sharpe；该策略的目标是跨市场可迁移的风险控制与配置，买入持有只作为回撤基准。但策略自身必须达到绝对 Sharpe 0.45 和最大回撤 25% 的门槛。

## 6. 数据解释边界

该实验验证的是**市场结构泛化**，不是某个人民币投资者能够直接实现的收益：

- 使用同一 Nasdaq 国家指数家族的指数点位；
- 不额外加入汇率对人民币收益的影响；
- 不模拟具体 ETF 的跟踪误差、税费、管理费、申赎和跨时区执行；
- 现金收益率设为 0；
- 执行仍采用下一共同交易会话收盘价 ± 0.05% 滑点，并收取 1% 单边费用。

如果未来进入 App 产品策略，还需要额外做可交易产品映射、FX、当地交易日历/时区和真实成本验证。
