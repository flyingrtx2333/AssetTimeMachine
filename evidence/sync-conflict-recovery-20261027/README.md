# Sync conflict recovery · 2026-10-27

旧版沿用上一天的记录没有继承来源。两端金额不同时，共同基准不足以证明哪一端是手工编辑，219 因此保留两端并暂停。发布、重启或反复刷新不会补出缺失的历史。禁止按设备时间猜测金额，也不为旧数据伪造继承标记。

本次在现有三方合并上补齐处理流程：

- 将金额、数量、手工单价、备注的真实分歧列为“资产／日期／字段”，每个字段须明确选择本机或云端。未完成选择不产生可应用的候选数据。
- 保留两端独立修改和后续新增日期。删除、结构、账户归属及缺少可靠基准的保护继续生效。
- 确认绑定账户、云端版本、共同基准和本机用户内容；确认期间发生新修改时重新核对。自动行情更新不使本机选择无故过期。
- 应用选择前私密保存两端备份，并原子保存候选和选择。断网、重启可继续；上传回执丢失时先核对已接受的版本，避免重复上传。
- 两端确实完全一致时，可恢复过期基准，避免旧重复记录再次造成伪冲突。新建／编辑记录继续使用已有继承来源规则。
- iPhone 与独立原生 Mac 共用差异正文，在当前云同步容器内切换。正文滚动、操作固定；未选择时 Return 不提交，选择完成后可提交，Escape 返回。金额包含 CNY，格式化不能掩盖两端小数差异，长备注完整显示。
